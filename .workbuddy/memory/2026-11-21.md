## 孩子宠物养成系统 v1.0 设计（仅设计，未实现）

- 产出：`C:\Users\34511\Desktop\pets\宠物养成系统设计.md`
- 需求要点：养蛋→孵化→长成宠物；喂牛奶+饼干；食物靠孩子完成自定义奖项赚积分兑换（示例：按时完成作业 = 10 积分）；宠物依次饲养，低阶毕业后进化成高阶的蛋，高阶食物需求更多。
- 确定的核心参数：
  - 汇率 1 积分 = 2 份食物（2 奶 / 2 饼 / 1+1 自由组合），单向不可逆。
  - 5 阶链：云团兽(12次) → 火苗狐(16) → 星角鹿(20) → 海雾鲸(24) → 星辰龙(30)。
  - 每阶单次配方递增：1+1 → 2+1 → 2+2 → 3+2 → 3+3 份；全程 102 次喂食 / 452 份（奶 246、饼 206）/ 226 积分，约 3 周。
  - 每阶 3 形态，阈值 ceil(K/3)、ceil(2K/3)；毕业同事务内生成下一阶蛋，旧宠物永久入图鉴。
- 设计原则：**只奖励不惩罚**（不扣分、不饿死、不掉级、断更不清零、图鉴不回收），数值全整数可心算，牛奶饼干缺一不可以制造「先规划再兑换」。
- 文档含 R1–R15 规则编号、10 个逻辑实体、孩子端 3 页/家长端 3 页、边界异常表、调参表、被否决方案表、验收清单，便于后续直接实现。
- 预留 `award.source_type = auto/external` 接口，可与已有英语练习工具（words_game / NCE1）共用积分账户。
- 待用户确认：默认数值、物种名称、是否启用二周目与英语工具联动。

## 架构与实现方案 v1.0

- 产出：`C:\Users\34511\Desktop\pets\宠物养成系统-架构与实现方案.md`
- 结论：本地单机 Web 应用 = Python Flask + SQLite 单文件 + Jinja2/原生 JS（零 npm、零外部服务、可离线）；`python app.py` 启动。否决了纯前端 localStorage（丢数据/无账本/无鉴权）、前后端分离+构建、Django、微服务、云同步优先。
- 六层架构：浏览器 → Web 路由（Blueprint/PIN/幂等）→ 业务服务 → **规则引擎（R1–R15 纯函数，核心资产，可脱离 Web/DB 单测）** → Repository → SQLite。
- 关键落地手段（用户重视 SQL 效率与约束下沉）：
  - 部分索引 `UNIQUE(child_id, award_id, claim_date) WHERE status='approved'` 防同日重复领奖且驳回不占额；
  - 部分唯一索引 `UNIQUE(child_id) WHERE status IN ('egg','juvenile','adult')` 在数据库层保证「只养一只」；
  - `request_log.request_id` 主键 + `INSERT OR IGNORE` 做写请求幂等，防孩子连点；
  - 流水为真相源，`points_balance`/`food_stock` 为冗余，提供 `verify_ledger.py` 重算校验；
  - SQLite WAL + `BEGIN IMMEDIATE` + `busy_timeout=5000`。
- 三大事务：兑换、喂食（含毕业分支：状态变更+图鉴+新蛋+切当前宠物同事务）、奖项确认（乐观锁只更 pending 行）。
- 鉴权：首次设 4–6 位 PIN，pbkdf2_hmac 加盐存 config.json；token 内存态重启失效；写接口全部校验。
- 实施路线 M1–M7：骨架 → 积分闭环 → 兑换闭环 → 养成闭环 → 家长端 → 加固 → 可选联动。建议先跑通 M2–M4 再补家长端。
- 英语工具联动采用「事件表投递 + 复用 AwardService.grant()」，禁止外部直接 UPDATE 余额。

## Bug 修复：家长端系统设置页显示 undefined（用户截图反馈）

- 现象：6 个配置项输入框全部显示字符串 "undefined"，且点保存 500。
- 根因1（显示）：PyMySQL 对 MySQL `JSON` 列返回的是**字符串**，`settings.get_all()` 未反序列化；前端 `v.rate`/`v.points` 取字符串属性 → undefined。修：`get_all()` 用 json.loads 解析；前端 `parent_settings.html` 改为显式 FIELD 映射表，并为 form_thresholds（无对应分支会 fallback 到 v.version）做专门显示/构建处理。
- 根因2（保存 500）：`app_config.updated_by` 是 BIGINT，代码传的是用户名字符串 "admin" → MySQL DataError 1366。修：schema.sql 改 VARCHAR(64) 并在线 ALTER TABLE，与 config_audit.operator 保持一致。
- 验证：API 返回全部为 dict；Node 模拟前端逻辑 6 项显示值全正确；配置保存/还原/审计记录均 200 正常。
